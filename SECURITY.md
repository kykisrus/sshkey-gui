# Политика безопасности

## Что приложение передаёт и что нет

**Передаётся** — на выбранный вами сервер, по SSH, только одна строка: публичный ключ
из `~/.ssh/<ключ>.pub`. Это единственный сетевой обмен, который инициирует программа,
кроме TCP-проверки доступности порта на том же хосте.

**Не передаётся** — приватные ключи, пароли, содержимое файлов, имя пользователя,
список каталогов, телеметрия, аналитика, обновления и любые обращения к внешним
сервисам. В интерфейсе нет CDN, внешних шрифтов и картинок.

## Модель угроз

Приложение рассчитано на один компьютер одного пользователя.

| Риск | Как закрыт |
|---|---|
| Доступ к интерфейсу из сети | HTTP-сервер слушает только `127.0.0.1` |
| DNS-rebinding | принимаются только заголовки `Host: 127.0.0.1:<порт>` / `localhost:<порт>` |
| Утечка пароля в файлы и логи | пароль живёт в памяти и в переменной окружения одноразового askpass-скрипта (`/tmp`, `700`), скрипт удаляется сразу после попытки |
| Утечка пароля в журнал | журнал пишет только метод и путь запроса |
| Дубликаты ключей | перед добавлением выполняется проверка на точное совпадение строки |
| Слишком открытые права на сервере | `umask 077`, каталог `700`, файл `600` |
| Подстановка спецсимволов из комментария ключа | строка ключа экранируется через `shlex.quote` |
| Случайная выгрузка приватных ключей | в архив они попадают только при явной отметке «включить приватные ключи» |
| Запись за пределы каталога ключей при создании | имя файла проверяется регулярным выражением, пути не принимаются |
| Штрафы sshd за перебор ключей | используется только выбранный ключ, `IdentitiesOnly=yes`, `IdentityAgent=none` |

## Известные ограничения

- Локальные процессы того же пользователя могут обращаться к `127.0.0.1:<порт>`.
  Приложение не заменяет песочницу или отдельного пользователя.
- Ключи с парольной фразой не поддерживаются.
- При первом подключении к новому хосту используется `StrictHostKeyChecking=accept-new`:
  отпечаток нового хоста принимается автоматически. Для строгой проверки заведите
  запись в `~/.ssh/known_hosts` заранее.
- Пароль передаётся системе через переменную окружения дочернего процесса. На Linux
  её может прочитать процесс того же пользователя (или root). Для машины с
  недоверенными локальными пользователями этот способ не подходит.

## Файлы, которые создаёт приложение

- `~/.config/sshkey-gui/settings.json` — только список дополнительных каталогов с ключами.
- `~/.ssh/<имя>` и `~/.ssh/<имя>.pub` — если вы создали ключ через приложение.
- Временный askpass-скрипт в `/tmp` — удаляется сразу после попытки передачи.
- Архив с ключами — только там, куда его сохранит браузер по вашей команде.

## Сообщения о проблемах

Если вы нашли уязвимость, опишите её в issue без публичных эксплойтов и без реальных
адресов и ключей. Не прикладывайте приватные ключи, пароли и внутренние IP.
